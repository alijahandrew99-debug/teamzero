## Today's work: shipped one fix

`git fetch origin --prune` found the same 42 tracked branches as
yesterday — zero new `keeper/*`/`audit/*` branches, `keeper-audit`
unchanged since 11-04 (`deaee35`), `main` unchanged. Rather than
re-running yesterday's already-confirmed merge-batch checks on an
unchanged backlog, picked up a standing, well-scoped gap from the
queue (restated in item 38's trailer, originally flagged 09-16):

**`lib/stripe.js`'s `verifyWebhook()` had no replay-timestamp
tolerance.** It checked only the HMAC over `t.<body>`, never whether
`t` itself was recent — so any captured valid `Stripe-Signature`
header (server logs, a compromised proxy hop, browser devtools
history on a shared machine) stayed forever replayable against
`/webhook/stripe`. Copied the fix shape Dawnpipe's own outbound
webhook verifier (`lib/hooks.js`) already uses — a 300s tolerance on
`t`, the same default Stripe's own libraries use.

Branch: **`keeper/2026-11-08-stripe-webhook-timestamp-tolerance`**

- New standalone suite `test-stripewebhook.js` (7/7): fresh signed
  event verifies; one 10 minutes old or 10 minutes in the future is
  rejected; one just inside the 300s window still verifies; a bad
  signature is rejected regardless of timestamp freshness; a missing
  timestamp is rejected; a caller-supplied shorter tolerance is
  honoured.
- Confirmed the test actually catches the gap, not just passes by
  coincidence: stashed the fix, 4/7 failed against unpatched `main`;
  restored it, 7/7 pass.
- `node --check` clean on `lib/stripe.js`; all six pre-existing
  suites still pass, 103/103, unaffected (none exercise the Stripe
  webhook route).
- Cut fresh off current `main` — a direct fast-forward merge,
  conflict-free by construction. Also checked it against every other
  open branch: none of the other ~20 touch `lib/stripe.js`, so it's
  conflict-free against the whole standing bundle too.

Smallest item in the backlog by severity (no known live exploitation
path today — this closes a *capability*, not an active attack seen
in the wild) but genuinely zero-risk to merge whenever convenient.
