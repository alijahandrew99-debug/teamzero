## Today's finding: a live bug is duplicate-emailing customer leads

A new independent audit run (separate from this Keeper shift, branch
`keeper-audit`) landed overnight and found two **High**-severity, reproduced
bugs. Both already have fixes pushed. I independently re-verified both today
rather than shipping something new — read the live code myself, read both
diffs, re-ran the merge and test checks in an isolated worktree.

**1. Duplicate sends (`audit/2026-09-23-send-lock-duplicate`) — actively live since 09-15.**
The one-send-per-account lock is supposed to stop a second click from
starting a concurrent send run. Its staleness check compares a job's *total
age* against 30 minutes, but the code's own comment says "no progress for 10
minutes" — a much stricter, different check. Default email pacing is
180–450s between sends, so a completely healthy run looks "stale" by about
its sixth email. A second click (now the natural thing to do, since
`a70c1ec` a week ago made one-button "send everything" the primary path)
force-expires the still-running job, releases the lock, and starts a second
run over the same still-approved drafts — nothing tells the first run to
stop. Every remaining recipient gets the cold email twice, silently, from a
domain whose whole reputation strategy (warmup ramp, pacing, daily cap) is
built on one send per recipient. Fix re-measures staleness from actual
progress instead of age, tells a force-expired job to stop, and re-checks
each item's status immediately before sending.

**2. Corrupted request bodies (`audit/2026-09-23-readbody-utf8`).**
`readBody()` decodes each TCP chunk on its own instead of buffering and
decoding once at the end — any multi-byte UTF-8 character split across a
chunk boundary (routine for any body over ~1400 bytes) comes out mangled.
For the Stripe webhook, those are the exact bytes the signature HMAC is
computed over: a genuine payment event with a non-ASCII byte anywhere in it
(a customer's name, address) can verify as a forgery and get rejected with a
400 — silently dropping a subscription change. Fix buffers as `Buffer`s and
decodes once.

Both merge clean against current `main`, alone and combined, verified via a
real `git merge --no-commit --no-ff` (not the coarser `git merge-tree`).
`node --check` and the relevant test suite pass on the merged tree.
