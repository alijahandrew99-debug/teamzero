    row, so a number that went quiet 30 days and then re-offended got a
    duplicate row inserted under the same id — every later read found the
    stale zero-points row first, so auto-block could never re-arm for that
    number again, and `spamwatch.json` grew a duplicate row per strike,
    unbounded. Fix is correct and tested (new decay-then-restrike test,
    22/22 in `test-spam.js`).
  - **voice-webhook-log-flood** (queue item 18, new): real live bug. The
    unauthenticated bad-Twilio-signature path in `server.js` logged on every
    rejected request via `logActivity`, which rewrites the whole activity file
    synchronously — an attacker hammering that path could stall every live
    call on this single-threaded server. Fix throttles that one log line to
    once/minute (global, not per-IP, since the point is capping total write
    rate against an attacker who picks their own source IPs).
  - **duplicate-caller-history** (queue item 19, new): perf-only, no behavior
    change. `/voice/incoming` called `stats.callerHistory()` three separate
    times on the greeting path (where the caller hears silence while it runs);
    now looked up once and reused.
